The interface

The Minitel's DIN port is a 5 V-era serial port: its TX (pin 3) is an open collector, its RX (pin 1) is pulled up inside the Minitel. The interface is the classic one-transistor design published by arduiblog in "Ressuscitez le Minitel" (2019), built here unchanged except for two things: it is powered from the XIAO's 3V3, not 5 V, and a 9.1 kΩ resistor sits in series on the line to D7.

  • Minitel → XIAO. R3 pulls the Minitel's open-collector TX up to 3V3, so the XIAO only ever sees 0–3.3 V. R4 (9.1 kΩ) limits the current into D7 if anything goes wrong.
  • XIAO → Minitel. Q1 is a common-base stage: its base sits at a fixed voltage set by R1 and R2. When D6 goes low, the emitter is pulled down, Q1 conducts and pulls the Minitel's RX low. When D6 is high (3.3 V), Q1 is off and the Minitel's own pull-up holds the line high. The stage does not invert, which matters: the nRF52840's UART cannot invert its signals.
  • Ground. DIN pin 2 to the XIAO's GND. Pins 4 and 5 stay unconnected. Pin 5 is a supply output on the Minitel 2 (8.5–15 V): insulate it and keep it away from the XIAO.

Parity errors at 9600 baud? The 220 kΩ pull-up is weak, and D7 picks up glitches from the CRT (hundreds of sub-20 µs spikes per 200 ms were measured). The UART filters them at 1200 baud. If link log shows parity errors at 9600, lower R3 to about 10 kΩ.

The DIN plug

Check before connecting the XIAO. With the Minitel switched on, a multimeter between pin 2 and pin 5 shows 8.5–15 V. That confirms the orientation of the pin numbers, and it is the pin you must never wire.

  • I2C moves to the NFC pads. The XIAO variant normally puts I2C on D6/D7. The Minitel env removes those defines and builds with -D CONFIG_NFCT_PINS_AS_GPIOS -D PIN_WIRE_SDA=30 -D PIN_WIRE_SCL=31. The first boot writes the UICR so that the two NFC pads (P0.09, P0.10) become GPIOs; this stays in the chip, and NFC can no longer be used on that board. I2C sensors, if any, go on those two pads at the back of the XIAO.
  • Nothing else uses Serial1. GPS is compiled out. USB serial carries the local command line.
  • Keep the DIN cable short.

Bring-up test (optional)

Before flashing MeshCore, the stand-alone sketch in firmware/minitel-test/ checks the link alone: it logs every byte the Minitel sends and takes commands on USB (115200 baud, type help).

cd firmware/minitel-test
pio run -t upload --upload-port /dev/ttyACM0

Verified on a Philips Minitel 2 (ROM Bv9): ENQROM, status and speed query, screen text and the keyboard at 1200 baud in Vidéotex; then speed 9600, mixte, echo off for 80 columns at 9600 baud with clean input and no parity errors. The speed acknowledgement arrives while the UART restarts and loses its first bytes, so speed confirms with a fresh speed query. The sketch also has a sense command that tells which DIN pin D7 is wired to.

Build and flash the firmware

The firmware is MeshCore's companion radio with the Minitel UI, on the companion-minitel branch of the firmware fork (code in examples/companion_radio/ui-minitel/). With PlatformIO:

git clone -b companion-minitel <firmware repository> meshcore-minitel
cd meshcore-minitel
pio run -e Xiao_nrf52_companion_minitel -t upload --upload-port /dev/ttyACM0
  • Flashing keeps the file system: the identity, contacts, channels and the Minitel history survive an update.
  • Upload sometimes fails on the 1200-baud "touch" that resets the XIAO into its bootloader. Retry, or double-tap the XIAO's reset button and upload to the bootloader's port.
  • Each build keeps its ELF as .pio/build/Xiao_nrf52_companion_minitel/firmware-<commit>.elf, so a crash record can be resolved to a source line later (see crash capture).
  • Native unit tests (googletest): pio test -e native -f test_minitel and -f test_minitel_emoji.

First boot

  1. Plug the DIN cable into the Minitel, power the XIAO, switch the Minitel on.
  2. The Minitel starts on its local "répertoire" page. Leave it with Fnct + Sommaire (see below). The firmware probes 9600, 1200, 4800 and 300 baud every 3 s, finds the terminal, switches it to 9600 baud, sets 80 or 40 columns and turns the local echo off. The welcome page appears; any key enters the service.
  3. Pair the phone app (MeshCore) over Bluetooth if you want it alongside: the default pairing code is 123456; change it in Réglages 15.
  4. Set the clock (Sommaire 6, or let the app or two agreeing nodes set it), the node name and position (Réglages 1 and 2), and your département for the regions (Réglages 6).
  5. 40 or 80 columns: Réglages 10. The choice is saved.

The Minitel's own keys

A few things are done on the Minitel's keyboard, not by the firmware. Fnct combinations: press Fnct with the letter, release both, then press the next key.

KeysEffect
Fnct + SommaireLeave the répertoire (the local page after power-on or standby).
Fnct + E, then ADisable the automatic standby.
Fnct + T, then VBack to Vidéotex from the Téléinformatique mode (where the protocol goes silent).

Whenever the Minitel is switched off or falls asleep, the node keeps working: messages go to the history, direct-message retries continue and the app is served. When the terminal comes back, the firmware notices it, sets it up again and shows the welcome page.

Back up the identity

The node's identity is its private key. If the file system is ever erased, the node gets a new key and your correspondents see a new, unknown node. Back it up once, over USB (115200 baud, CR line ends):

get prv.key        # prints 128 hex digits: save them offline
set prv.key <hex>  # restore, then reboot

The private key is a secret. Anyone who has it can impersonate the node and read its direct messages. Never paste it into a chat, a ticket, a log or a screenshot; keep it offline, readable only by you. The Minitel itself never shows, imports or generates keys.
